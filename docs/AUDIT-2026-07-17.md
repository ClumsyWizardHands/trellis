# Audit — external adversarial review (2026-07-17)

An external audit applying trellis's own doctrine to trellis: attack → independently
verify each break against the real code (a *second* agent, fresh reading) → fix at the
root, regression-first → re-attack. Confirmed breaks are fuel, logged plainly. The
honest structural-vs-advisory line from `VERIFICATION.md` is held throughout.

Baseline environment: Python 3.14.4 (venv), core installs clean (`pip install -e .`)
and with the web extra (`pip install -e '.[web]'`; the web app also needs
`python-multipart`, which is pulled by FastAPI form handling — worth adding to the
`[web]` extra).

## 2. Confirmed defects (most severe first)

Each was independently re-derived by a second agent from a fresh reading (maker ≠
verifier). Regression test written **before** the fix, per the house rule.

### D-1 · HIGH · refusal #5 bypassed on the actual approval surface (web)
- **Repro:** stage an action `created_by="witness"`; `POST /approve` with
  `human=witness`. The endpoint records an authoritative `staged_action` "approved"
  event and the action leaves the pending inbox — the staging agent self-approved.
- **Root cause:** `web/app.py::_record_decision` wrote the lifecycle event that
  `views.inbox()` reads as truth, but never applied the independence guard
  `stage.Outbox.approve` enforces. The library refuses this; the UI (the surface the
  README presents as where approve/deny happen) did not.
- **Fix:** pure `views.approval_guard(ledger, action_id, human)` — named human +
  real staged action + `same_identity(human, staging_author)` refusal — raised as
  `HTTPException(403)` from `_record_decision`; `/affirm` rejects blank human with
  400 (was an ungraceful 500).
- **Independent verification:** CONFIRMED + SOUND (reverted the fix, showed the
  self-approval succeeded pre-fix and 403s post-fix, in-process and over live HTTP).

### D-2 · HIGH · refusal #5 bypassed via homoglyph, in the core
- **Repro:** `Outbox.approve(aid, "witnеss")` (Cyrillic е, U+0435) on an action
  `created_by="witness"` **succeeds** — the staging agent self-approves in disguise.
- **Root cause:** the approval gate used only `same_identity`, which deliberately
  does *not* fold confusables (folding would wrongly merge distinct real names like
  `мир`/`mir`). The real defense — the ASCII-identity allowlist `require_identity`,
  which *refuses* exotic ids — was wired into the verification gate
  (`verify._guard_independence`) but **not** the outbound-approval gate. So the most
  consequential refusal lacked the defense its sibling refusal had.
- **Fix:** `stage.Outbox._require_approver` calls `require_identity` (refusing a
  non-ASCII/exotic approver id) before `same_identity`, on both `approve` and `deny`;
  the web `approval_guard` does the same. An exotic id is **refused, not reasoned
  about** — parity with the verifier gate.
- **Independent verification:** CONFIRMED (library bypass reproduced) + fix re-run
  (now refused; 225 pass; 10/10 stress).

### D-3 · MEDIUM · satisficing hole in `curiosity.resolve()`
- **Repro:** ask a question; append *any* live decision that postdates it (subject:
  "hiring plan for Q3", unrelated); `resolve()` **closes** the question citing it.
- **Root cause:** the close required only that some cited entry be live, non-machinery,
  and postdating — never that the move came from pursuing *this* question. That is the
  exact "I did some work, therefore I understand" laundering the module exists to
  forbid, one step removed from the dry-seek case it already blocks.
- **Fix:** the cited map-move must appear in the `delta_refs` of a **non-dry seek of
  this assumption** (`map_changed=True`, postdating the question) — tying the close to
  a recorded pursuit of *this* question.
- **Honest boundary (advisory, labelled in code):** the seek is a self-report, so a
  determined agent could still fabricate a non-dry seek. This is a strictly higher bar
  (a durable, attributed false record vs. pointing at incidental activity), not an
  airtight proof; no lexical test proves a delta is *about* an assumption. `dry_streak`
  does **not** catch it (it counts only consecutive dry seeks) — the real backstop is
  the human reading the cited seek + delta on the Curiosities board. (The first draft
  of the fix's comment overclaimed the streak rail caught this; corrected.)
- **Independent verification:** CONFIRMED + SOUND, not over-tightened (the legitimate
  close path still works); the residual self-report gap was flagged by the verifier and
  is stated here honestly.

### Not fixed — a decision for the human (recorded, not patched)
- **Ingestion batch-abort / resume-wedge.** One malformed observation candidate (an
  opinion-T with no POVs — a plausible model output) raises loudly out of
  `Ingestor.ingest`, which is *intended fail-loud* (pinned by
  `test_opinion_T_without_povs_leaves_no_half_written_pair`). But the raise aborts the
  whole batch, and the item re-crashes on every resume, blocking healthy later items.
  The module already has a "record the rejection, continue" path for `accept=False`;
  extending it to construction errors would remove the wedge while preserving "no
  silent failure" — but it changes a pinned test's expectation, so it is flagged as a
  decision, not done unilaterally.

## 4. Improvements in the spirit (ranked by leverage)

1. **Rebuildable in-memory ledger index (structural).** *What:* cache parsed entries in
   the `Ledger` instance and append incrementally; maintain the superseded-set and
   valid_to-map incrementally so `active()`/`get()`/`active_head()` are O(1)/O(k), not
   O(n). *Why:* the whole thesis is "compounds over months," but today it compounds into
   **O(n²) writes** — building 10k decisions took **230 s** (every `record()` re-parses
   the whole file; a supersessing append parses it 3×), and single reads are O(n) (~44 ms
   at 10k → ~450 ms projected at 100k, several per page/append). The contemplative backdrop
   ("every decision in every transcript, every day") will hit this fast. *Constraint honored:*
   the file stays the sole authority; the index is derived and rebuildable on open — never a
   second source of truth; append-only/bitemporal/greppable untouched. *Cost:* medium.
   *Risk to invariants:* low.
2. **A real model-backed detector/confirmer for `observe` (structural).** *What:* wire the
   detector under one agent-id+model and the confirmer under a *different* id + cheaper model
   with fresh context (the `panel.py` refute-oriented, confidence-aware pattern), via the
   existing `Provider` seam. *Why:* closes the single biggest gap between the vision and the
   running system, and keeps maker≠confirmer real when both are models. *Cost:* medium-high.
   *Risk:* low (the seam and the panel already exist).
3. **Close the affirmation → confidence loop (structural, small).** *What:* make an affirmation
   actually raise standing — a derived affirmed-confidence on the Map and/or a contribution to
   the maker's `trust_record` — kept as an *output, never a gate*. *Why:* the UI copy literally
   says "affirming compounds confidence," but affirmations are only counted and displayed;
   nothing compounds. Canon-as-output (plan §4) is asserted but not wired. *Cost:* low.
   *Risk:* low.
4. **Ingestion resilience — isolate per-candidate failures (decision for the human).** *What:*
   treat a candidate construction error like the existing `accept=False` path — record it
   loudly as a rejected `observation_check` and continue. *Why:* preserves "no silent failure"
   while removing the batch-abort/resume-wedge (see D-3's sibling above). *Cost:* low.
   *Risk:* changes a pinned test's expectation → the human's call.
5. **Understanding depth — carry the reasoning, not just the outcome (advisory).** *What:*
   attach `conversation_velocity` (already computed, currently unused on nodes) to observations
   as context; let observations record the room's **dissent** even for Y/N (not only T's POVs);
   capture the **shift-from-prior-position** explicitly when an observation supersedes a prior
   read (the supersession chain exists; the reasoning transition is not recorded). *Why:* the
   stated goal is "how the room got there," but a decision today is anchor+subject+verdict+
   rationale (+POVs for T). *Cost:* medium. *Risk:* low.
6. **Comprehension UX nits.** Frontmatter booleans render as Python `True`/`False`, which YAML
   1.2 / Obsidian parses as *strings*, not booleans (emit lowercase `true`/`false`). The
   affirmation copy overclaims until #3 lands. Add `python-multipart` to the `[web]` extra so
   the app starts without a manual install.

## 5. The honest verdict

**Structural guarantees — held, or made to hold.** The five refusals, the one
current-truth resolver (`active()` = not-superseded ∧ in-validity), the anti-fork on the
homoglyph-folded question-key (through `resolve()`), the two-node observation model with
distinct stable identities, provenance FLOOR+OR propagation, ingestion idempotency +
crash/resume, the vault reconciler (human edit folded and attributed; retirement/supersession
reflected live; missing files surfaced), the reflection self-modification gate (re-derives an
independent verdict from the record; refuses forged `verified` flags; cadence keyed off
write-time), and bounded loops with a `finally`-written outcome all survived their breakers —
including a full contemplation-day flow that reconstructed correctly across three process
restarts from the file alone. Two of the five refusals (#5 on the web, #5 via homoglyph) had
real bypasses; both are now closed at the root and regression-pinned, bringing the approval
gate to the same ASCII-allowlist defense the verification gate already had.

**Advisory heuristics — honestly bounded, not oversold.** The embodiment/dread lints, the
synthesis-justification test, and pass-substance remain best-effort lexical gates that cannot
be made adversarially complete — correctly labelled advisory, backed by the identity allowlist
and human review. The curiosity-close tie (D-3's fix) joins them: it converts a *trivial*
structural hole (cite any postdating entry) into an *advisory* boundary (must fabricate a
durable false seek) — a real improvement, honestly not airtight.

**Confidence.** High on the structural findings and fixes — each was reproduced, fixed
regression-first, and independently re-derived by a second agent. Medium on completeness: this
pass concentrated on the newest code and the cross-module/UI seams (where unit coverage is
thinnest) and did not re-run the full 50-agent gauntlet on the older core, which prior rounds
already converged. Where I was unsure — the ingestion batch-abort's intended severity, the
YAML-boolean rendering in a real Obsidian install — I have said so rather than asserted.
